# Stack Research

**Domain:** Universal structured logging library (Node / Bun / Deno / Cloudflare Workers)
**Researched:** 2026-03-20
**Confidence:** HIGH (npm registry versions verified, tool choices cross-referenced with official docs)

## Recommended Stack

### Core Technologies

| Technology | Version | Purpose | Why Recommended |
|------------|---------|---------|-----------------|
| TypeScript | 5.9.3 | Source language | Current stable release (5.8 GA Feb 2025, 5.9 current). `verbatimModuleSyntax` + `isolatedModules` enforced for clean ESM-only output compatible with esbuild single-file transpilation. Source TypeScript, ship `.d.ts`. |
| tsup | 8.5.1 | Build / bundler | Powered by esbuild. Handles ESM output, `.d.ts` generation, and multiple entry points (subpath exports) with minimal config. Industry standard for TypeScript library authoring in 2025. No CJS output needed — ESM only per project constraints. |
| Vitest | 4.1.0 | Testing framework | Fastest TypeScript test runner with native ESM support. Node >= 20 required. Works with Bun as package manager (`bun run test`, not `bun test`). Deno 2.5.x has a known panic with Vitest 4.0.10+, but the library runs on Deno — tests run on Node/Bun. |

### Supporting Libraries

| Library | Version | Purpose | When to Use |
|---------|---------|---------|-------------|
| @changesets/cli | 2.30.0 | Release and changelog management | Needed for every release. Controls semantic version bumps manually (unlike semantic-release which auto-cuts on every merge). Better fit for a deliberate release process. |
| typescript-eslint | 8.57.1 | Linting with type-aware rules | Dev-time code quality. ESLint 9 flat config is the current standard. Use `tseslint.configs.recommended` as the baseline — strict mode optional but worth enabling. |
| @eslint/js | latest | ESLint core (flat config) | Required peer for typescript-eslint with flat config. |

### Development Tools

| Tool | Purpose | Notes |
|------|---------|-------|
| tsup (config: `tsup.config.ts`) | Compile TypeScript to ESM with `.d.ts` | `entry` object maps source entrypoints to dist outputs. Set `format: ['esm']` only — no CJS. Set `dts: true`. Use `splitting: false` for a logging library (single file per entrypoint). |
| `jsr publish` / `npx jsr publish` | Publish to JSR registry | Uses `jsr.json` (or `deno.json`). JSR accepts TypeScript source — no pre-compilation step needed for JSR publish. The npm compatibility layer under `@jsr/` scope is auto-generated by JSR. |
| `npm publish` | Publish to npm registry | Publish the compiled `dist/` output with `package.json` exports. Separate step from JSR. |
| GitHub Actions | CI, automated publishing | OIDC token auth for JSR (no stored secrets). npm publish requires `NPM_TOKEN` secret. Run tests on Node 20 + Node 22 + Bun. |

## Alternatives Considered

| Recommended | Alternative | When to Use Alternative |
|-------------|-------------|-------------------------|
| tsup | unbuild / rollup / tsdown | `unbuild` is fine for monorepos with Nuxt/UnJS conventions. `tsdown` (the tsup successor by the same author) is in active development and may replace tsup in 6-12 months — watch it. `rollup` gives more control but requires more config. For this project, tsup's defaults align perfectly. |
| tsup | tsc directly | Only if you need zero-dep build toolchain and can live without bundled output. tsc alone cannot produce a single merged entrypoint or handle multiple subpath exports cleanly. |
| Vitest | Jest | Jest requires additional ESM config (`--experimental-vm-modules`, or Babel transform). Vitest is native ESM. No reason to choose Jest for a greenfield ESM library. |
| Vitest | Node native test runner (`node:test`) | `node:test` is viable and zero-dependency for CI, but lacks the DX: no watch mode, no snapshots, weaker assertion API. Not worth the tradeoff for development velocity. |
| @changesets/cli | semantic-release | semantic-release cuts a release on every PR merge based on commit messages — too aggressive for a library where you want deliberate release timing. Changesets lets you batch changes into a curated release. |
| @changesets/cli | release-it | Both are good for single-package repos. Changesets has broader adoption in the TypeScript library ecosystem (used by Vite, Vitest, tRPC, Radix). |
| ESLint 9 flat config | Prettier | Formatting: ESLint's stylistic rules or Prettier — either works. For a small library, add `eslint-config-prettier` if using Prettier, or skip it and rely on ESLint `stylistic` rules. Not a critical decision. |

## What NOT to Use

| Avoid | Why | Use Instead |
|-------|-----|-------------|
| CommonJS output (`cjs` format in tsup) | Project explicitly targets modern runtimes with ESM-capable bundlers. Adding CJS doubles build output, complicates `package.json` exports, and has no stated use case. The ESM spec is settled. | ESM only. Consumers on old CJS-only toolchains are explicitly out of scope. |
| Winston | Node.js only (no Bun/Deno/Workers), heavy runtime deps, not structured-first | Custom zero-dep implementation (which is the project itself) |
| Pino | Node.js only, no native browser/Workers support, worker_threads dependency | Custom zero-dep implementation |
| AsyncLocalStorage for context propagation | Not available in Cloudflare Workers (the primary prod target). Adds implicit magic and runtime coupling. | Explicit `withContext()` as already decided in PROJECT.md |
| Monorepo (turborepo / nx / pnpm workspaces) | Single package with subpath exports is the stated architecture. Monorepo tooling adds overhead without benefit when there is exactly one package. | Subpath exports in a single `package.json` |
| Babel / SWC for transpilation | tsup's esbuild handles TypeScript fast enough. Adding Babel/SWC is a second transpiler for no gain. | tsup (esbuild under the hood) |
| `isolatedDeclarations: true` (oxc-transform path) | Still experimental / unstable in TypeScript 5.x — production risk for a library shipping type declarations. | Standard `dts: true` in tsup which uses `tsc` for declarations — stable and correct. |

## Stack Patterns by Variant

**For the dual npm + JSR publish:**
- Use two separate CI jobs (or steps): one for `npm publish` (compiled dist), one for `npx jsr publish` (TypeScript source).
- JSR does NOT need pre-compiled output. Point `jsr.json` exports at `src/index.ts` directly.
- npm DOES need compiled output. Point `package.json` exports at `dist/`.
- Version must be kept in sync between `package.json` and `jsr.json`. Use changesets to bump `package.json`, then mirror to `jsr.json` in the release script.

**For subpath exports (`slog` + `slog/hono`):**
- tsup `entry` object: `{ index: 'src/index.ts', hono: 'src/hono.ts' }`.
- `package.json` exports: explicit `"."` and `"./hono"` subpaths, each with `types` (first), `import`, `default` conditions.
- `jsr.json` exports: same two subpaths, pointing at `src/index.ts` and `src/hono.ts`.
- TypeScript `moduleResolution` in tsconfig must be `Bundler` or `NodeNext` for conditional exports to resolve in consumer projects.

**For Cloudflare Workers compatibility:**
- No Node.js built-ins in the core (`process`, `fs`, `os`, etc.). Use `typeof console !== 'undefined'` guards only if needed.
- No `AsyncLocalStorage`. No `worker_threads`. No `stream`.
- The core logger must pass the CF Workers `no-nodejs-compat` constraint: pure JavaScript objects, `console`, and `fetch` only.

## Version Compatibility

| Package | Compatible With | Notes |
|---------|-----------------|-------|
| tsup@8.5.1 | TypeScript 5.x | tsup uses esbuild for JS transpilation, tsc for `.d.ts`. TypeScript 5.9 is compatible. |
| vitest@4.1.0 | Node >= 20.0.0 | Vitest 4 dropped Node 18. This is acceptable — Node 18 is EOL as of April 2025. |
| vitest@4.1.0 | Bun (as pkg manager) | Works with `bun run test`. Bun's native test runner bypasses Vitest if you use `bun test` — don't. |
| vitest@4.1.0 | Deno | Known panic in Deno 2.5.6 with Vitest 4.0.10+. Use Node for running tests in CI; test against Deno manually or in a separate compatibility check job. |
| typescript-eslint@8.57.1 | ESLint 9, TypeScript 5.x | ESLint 9 flat config is required. Legacy `.eslintrc` format is deprecated. |
| @changesets/cli@2.30.0 | Any npm workflow | Works standalone with `package.json`. No monorepo tooling required. |
