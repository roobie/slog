  <action>
Create `.github/workflows/` directory and the `publish.yml` file.

The workflow must:

1. **Trigger** on push of tags matching `v*`
2. **Single job** named `publish` running on `ubuntu-latest`
3. **Permissions:** `contents: read`, `id-token: write` (required for npm OIDC and JSR OIDC)
4. **Steps in order:**
   a. `actions/checkout@v4`
   b. `actions/setup-node@v4` with `node-version: '22'` and `registry-url: 'https://registry.npmjs.org'`
   c. `npm ci`
   d. Type check: `npx tsc --noEmit`
   e. Test: `npm test`
   f. attw check: `npx @arethetypeswrong/cli --pack . --ignore-rules cjs-resolves-to-esm`
   g. Publish to npm: `npm publish --access public --provenance` with env `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`
   h. Publish to JSR: `npx jsr publish --provenance`

Use these exact step names: "Checkout", "Setup Node", "Install dependencies", "Type check", "Test", "Check types (attw)", "Publish to npm", "Publish to JSR"

The workflow is atomic by design: steps run sequentially, so if attw or tests fail, publishing does not happen. If npm publish fails, JSR publish does not run (both must succeed for the workflow to be green).

After creating the workflow, run the local verification commands to confirm the package is ready:
- `npx @arethetypeswrong/cli --pack . --ignore-rules cjs-resolves-to-esm`
- `npx jsr publish --dry-run` (if jsr CLI is available; install it first with `npm install -g jsr` or use npx)

If attw reports issues, document them. If jsr dry-run reports slow types, fix them.
