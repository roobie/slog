   ```typescript
   export type LogLevel = 'trace' | 'debug' | 'info' | 'warn' | 'error' | 'fatal';

   export interface LogEntry {
     level: LogLevel;
     timestamp: number;        // Unix ms via Date.now()
     message?: string;
     context: Record<string, unknown>;
     data: Record<string, unknown>;
   }

   export interface Plugin {
     name: string;
     transform(entry: LogEntry): LogEntry | null;
   }

   export interface Transport {
     write(entry: LogEntry): void;
     flush(): Promise<void>;
   }

   export interface Logger {
     trace(data: object): void;
     debug(data: object): void;
     info(data: object): void;
     warn(data: object): void;
     error(data: object): void;
     fatal(data: object): void;
     withContext(context: Record<string, unknown>): Logger;
     flush(): Promise<void>;
   }

   export interface LoggerOptions {
     level?: LogLevel;
     plugins?: Plugin[];
     transports?: Transport[];
     context?: Record<string, unknown>;
   }
   ```

   Key differences from wlog reference:
   - NO `error` field on LogEntry (errors live in data.error/data.err, handled by plugin)
   - Plugin is `{ name, transform }` not a bare function
   - Transport is `{ write, flush }` not a batch function
   - Log methods return `void` not `Logger` (no chaining)
   - 6 levels not 4

   ```typescript
   import type { LogEntry, LoggerOptions, Logger, Plugin, Transport, LogLevel } from './types.ts';
   import { LOG_LEVELS } from './levels.ts';
   ```

   Class LoggerImpl implements Logger:
   - Constructor: accepts LoggerOptions, defaults level to 'info', plugins to [], transports to [], context to {}
   - 6 log methods (trace/debug/info/warn/error/fatal) each call private `log(level, data)`
   - Private `log(level: LogLevel, data: object): void`:
     - FIRST LINE: `if (LOG_LEVELS[level] < LOG_LEVELS[this.minLevel]) return;` — NOTHING before this
     - Then: `const { message, ...rest } = data as { message?: string; [key: string]: unknown };`
     - Then: construct LogEntry with level, Date.now(), message, Object.freeze({...this.context}), rest
     - Then: call runPipeline(entry)
   - Private `runPipeline(entry: LogEntry): void` (SYNC, not async):
     - Loop over this.plugins
     - If current is null, return early
     - try { next = plugin.transform(current) } catch(err) { console.warn(`[slog] plugin "${plugin.name}" threw:`, err); next = current; }
     - After loop, if current !== null, push to this.buffer
   - `withContext(extraContext)`:
     - Create frozen merged context: `Object.freeze(Object.assign({}, this.context, extraContext))`
     - Return new LoggerImpl with same minLevel, same plugins array ref, same transports array ref, frozen context
   - `flush(): Promise<void>`:
     - If buffer empty, return
     - Splice buffer entries out
     - For each transport, call transport.write(entry) for each entry, then await Promise.allSettled of transport.flush() calls
     - Actually simpler: iterate buffer, call transport.write(entry) for each, then await Promise.allSettled(transports.map(t => t.flush()))

   Wait, I need to reconsider the flush design. Looking at the Transport interface:
   - `write(entry: LogEntry): void` — sync, per-entry
   - `flush(): Promise<void>` — async, batch send

   The logger.flush() should: take all buffered entries, for each transport call write() for each entry, then await all transport.flush() calls. This way the transport accumulates via write() and actually sends on flush().

   Actually that is overly complex for Phase 1. Simpler design that matches the research:
   - Logger has internal buffer (LogEntry[])
   - On log(): after pipeline, push to buffer
   - On flush(): splice buffer, for each transport call write() per entry, then Promise.allSettled all transport.flush()
